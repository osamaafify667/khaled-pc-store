# متجر خالد للكمبيوتر — KHALED PC STORE

متجر إلكتروني عربي (RTL) لبيع قطع الكمبيوتر والتجميعات الجاهزة، مع منشئ تجميعات يفحص التوافق، وسلة وشراء، ودفع نقدي أو تحويل إنستاباي يدوي، ولوحة تحكم كاملة للمخزون والطلبات والمحتوى.

- **الموقع:** الواجهة العربية الكاملة + لوحة التحكم
- **العنوان:** مول البستان، وسط البلد، القاهرة، مصر
- **العملة:** الجنيه المصري (ج.م)
- **اللغة:** العربية فقط حاليًا (الاتجاه RTL)

> هذا الملف يشرح التشغيل المحلي، الإعداد، النشر، النسخ الاحتياطي، وما لم يكتمل بعد.

## 1. الميزات

### واجهة المتجر

- صفحة رئيسية بتصميم داكن فاخر، خط Cairo، متوافقة مع الهاتف والتابلت.
- المتجر مع بحث، وفلترة حسب التصنيف والشركة، وترتيب حسب السعر/الأحدث/الأكثر مبيعًا، وصفحات.
- صفحة تصنيف لكل فئة (معالجات، لوحات أم، كروت شاشة، رامات، تخزين، مزودات طاقة، كيسات، تبريد، شاشات، كيبورد وماوس، تجميعات، إكسسوارات).
- صفحة منتج: صور، سعر، خصم، ضمان، مواصفات فنية مجمّعة، حالة المخزون، وحالة الكرتونة (بالكرتونة الأصلية / بدون كرتونة)، منتجات مشابهة، وإضافة للسلة.
- التجميعات الجاهزة في قسم مستقل `/prebuilt` مع تفاصيل المكونات.
- منشئ التجميعات `/builder`: اختيار المكونات، سعر إجمالي لحظي، فحص توافق مع نسبة توافق واكتمال، استبدال أي قطعة، بدائل متاحة لأي قطعة غير متوفرة، توصيات توافق داخل قائمة الاختيار، حفظ محلي في المتصفح، مشاركة رابط، حفظ التجميعة كرابط عام، إضافة التجميعة كاملة للسلة، وإرسالها إلى المتجر عبر واتساب.
- سلة شراء محفوظة على السيرفر (Cookie + قاعدة بيانات) تعمل للزائر بدون حساب.
- إتمام الطلب: توصيل أو استلام من المحل، تحقق من رقم هاتف مصري، شحن حسب المحافظة، كوبونات، ملاحظات، وقبول الشروط.
- صفحة نجاح الطلب مع رقم الطلب، الملخص، وتعليمات الدفع.
- تتبع الطلب من `/track` برقم الطلب + رقم الهاتف، وخط زمني للحالة.
- **لا يوجد تسجيل دخول أو حساب للعملاء:** الشراء كزائر فقط، وتتبع الطلب برقمه ورقم الهاتف.
- لوحة تحكم مخفية تمامًا: لا يوجد أي رابط لها في المتجر، وتُفتح على `/admin` بكلمة مرور فقط.
- صفحات: تواصل معنا (واتساب + بيانات المتجر)، الضمان، الاستبدال، الاسترجاع، الشحن، الخصوصية، الشروط والأحكام.
- صفحات 404 و500 مخصصة، Sitemap، robots، وبيانات منظمة (Product / Store / Breadcrumb).

### منشئ التجميعات وفحص التوافق

محرك توافق مستقل ونقي (بدون قاعدة بيانات) في `src/server/compatibility/`، ويعمل أيضًا في المتصفح للنتائج اللحظية، مع إعادة الحساب على السيرفر عند الطلب.

قواعد الفحص (20 قاعدة):

| المجال | ما يتم فحصه |
| --- | --- |
| المعالج واللوحة | المقبس، مجموعة الشرائح المدعومة، إصدار BIOS المطلوب، عائلة المعالج |
| الذاكرة | DDR4/DDR5، عدد الوحدات مقابل الفتحات، السعة القصوى، السرعة |
| اللوحة والكيسة | ATX / Micro-ATX / Mini-ITX |
| كارت الشاشة | الطول المتاح، سماكة الكارت (عدد الفتحات) |
| التبريد | ارتفاع المشتت الهوائي، مقاسات الرادياتير، دعم المقبس |
| التخزين | منافذ M.2، منافذ SATA، أماكن 2.5 و3.5 بوصة |
| الطاقة | القدرة الإجمالية المتوقعة، موصلات PCIe، موصلات CPU، طول المزود داخل الكيسة |

النتيجة واحدة من: **متوافق** / **تحذير** / **غير متوافق** / **بيانات غير كافية**. لا يخمّن المحرك أبدًا: عند غياب مواصفة لازمة يظهر تحذير "بيانات غير كافية" بدل افتراض التوافق. ويمكن للإدارة تعطيل أي قاعدة أو تجاوزها من جدول `CompatibilityRule`.

بجانب النتيجة تعرض الواجهة **نسبة توافق واكتمال** محسوبة من عدد الأخطاء والتحذيرات والبيانات الناقصة والخانات الفارغة — وهي للعرض فقط ولا تُغيّر قرار المحرك. كل قطعة غير متوفرة يمكن اختيارها لعرض أفضل **البدائل المتاحة** من نفس الفئة، وأي بديل يُعاد فحصه قبل اقتراحه. قائمة اختيار القطع تعرض حالة التوافق لكل منتج وترتب المتاح والمتوافق أولًا، ويوجد زر **إرسال التجميعة على واتساب** برسالة تحتوي القطع والإجمالي وحالة التوافق.

### لوحة التحكم `/admin`

- **مخفية وغير مرتبطة بأي صفحة في المتجر** ومستثناة من الفهرسة (`noindex` + `robots.txt`).
- الدخول بكلمة مرور فقط من `/admin/login` — بدون بريد إلكتروني، ويتم التحقق منها مقابل حسابات المديرين النشطين.
- لوحة معلومات من قاعدة البيانات: مبيعات مؤكدة، عدد الطلبات، بانتظار التأكيد، تحويلات بانتظار المراجعة، مخزون منخفض، عدد العملاء، رسم مبيعات يومي، الأكثر مبيعًا، وآخر الطلبات.
- المنتجات: إنشاء/تعديل، صور متعددة (رفع ملفات)، **صورة واحدة على الأقل مطلوبة**، **مواصفة فنية واحدة على الأقل مطلوبة**، **السعر أكبر من صفر مطلوب**، **تحديد الكرتونة (بالكرتونة الأصلية / بدون كرتونة) مطلوب**، مواصفات توافق جاهزة حسب التصنيف، حالة النشر (مسودة/نشط/مؤرشف)، استعادة المؤرشف، وسم "مميز"، ومشاركة المنتج عبر واتساب.
- تصدير المنتجات CSV واستيرادها (حتى 500 صف، 3 ميجابايت).
- المخزون: المتاح = الكمية − المحجوز، تعديل يدوي مع سبب إلزامي، وسجل حركات كامل (من قام بالتعديل ومتى ولماذا).
- الطلبات: فلترة وبحث وتصدير CSV، تفاصيل كاملة، تغيير الحالة حسب انتقالات مسموحة فقط، إلغاء مع تحرير الحجز، مراجعة تحويل إنستاباي (قبول/رفض)، فاتورة قابلة للطباعة، وزر واتساب لمراسلة العميل برقم الطلب وحالته.
- التصنيفات، الشركات، الكوبونات، مناطق الشحن والمحافظات، العملاء، المستخدمون، والإعدادات.
- الإعدادات: بيانات المتجر، الهاتف/واتساب/العنوان/مواعيد العمل/السوشيال، تفعيل الدفع النقدي والاستلام وإنستاباي وبياناته، الشحن المجاني، حدود المخزون، والـ SEO. رقم واتساب هنا يشغّل زر التواصل العائم في كل صفحات المتجر ورسائل التجميعات والمنتجات والطلبات.
- سجل نشاط (Audit Log) لكل إجراء حساس مع المستخدم والوقت وIP والتفاصيل.

### الطلبات والدفع

- الدفع نقدًا عند الاستلام، أو نقدًا عند الاستلام من المحل، أو تحويل إنستاباي يدوي.
- لا يصبح الطلب "مدفوعًا" أبدًا قبل مراجعة الإدارة للتحويل.
- حجز المخزون عند إنشاء الطلب، وتحريره عند الإلغاء، وخصمه فعليًا عند التسليم.
- أسعار وشحن وكوبون وإجمالي تُحسب على السيرفر فقط، مع نسخ (Snapshots) لأسعار البنود داخل الطلب.

### الأمان

- جلسات مخصصة بكوكيز `httpOnly`، وتُخزَّن بصمة SHA-256 للتوكن فقط.
- كلمات المرور بـ `scrypt` وملح عشوائي.
- تحقق من الصلاحيات على السيرفر في كل صفحة وإجراء إداري.
- تحديد محاولات تسجيل الدخول وقفل مؤقت بعد تكرار الفشل.
- تحقق Zod لكل المدخلات، ورفض الصور غير الصالحة بفحص بايتات الترويسة.
- لا توجد كلمة مرور افتراضية للمدير في الإنتاج.
- رؤوس أمان أساسية عبر `next.config.ts`.

### SEO والأداء

- Metadata ديناميكية لكل صفحة، Open Graph وTwitter.
- `sitemap.xml` و`robots.txt`.
- بيانات منظمة Product وStore وBreadcrumb.
- صور محسّنة عبر `next/image` مع AVIF/WebP.
- لوحة التحكم `noindex` ومخفية، ولا توجد صفحات حسابات عملاء.

### الاختبارات

98 اختبارًا تغطي: محرك التوافق ونسبة التوافق، حساب الأسعار والكوبونات والشحن، إنشاء الطلبات وإلغاءها وتحرير المخزون، سباق شراء آخر قطعة، القبول والرفض للتحويلات، صلاحيات المدير، والتحقق من المدخلات.

## 4. التشغيل المحلي خطوة بخطوة

### 4.1 تثبيت الحزم

```powershell
npm install
```

### 4.2 إنشاء ملف البيئة

```powershell
Copy-Item .env.example .env
```

ثم عدّل `.env`. الحد الأدنى المطلوب:

```env
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/khaled_pc_store?schema=public"
TEST_DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/khaled_pc_store_test?schema=public"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
ADMIN_EMAIL="admin@example.com"
ADMIN_PASSWORD=""
SEED_DEMO_DATA="false"
STORAGE_DRIVER="local"
```

- لا تضع `ADMIN_PASSWORD` في الإنتاج. استخدم `npm run admin:create` وأدخل كلمة المرور في الأمر ثم احذفها من `.env`.
- إذا كان PostgreSQL على منفذ مختلف (مثل 5433) غيّر الرقم في الرابطين.

### 4.3 إنشاء قواعد البيانات

```powershell
psql -U postgres -c "CREATE DATABASE khaled_pc_store;"
psql -U postgres -c "CREATE DATABASE khaled_pc_store_test;"
```

### 4.4 تطبيق الترحيلات وتوليد Prisma Client

```powershell
npm run db:generate
npm run db:migrate
```

- `db:migrate` يشغّل `prisma migrate dev` (للتطوير).
- في الإنتاج استخدم `npm run db:deploy` فقط.

### 4.5 إنشاء حساب المدير

```powershell
npm run admin:create -- --email "admin@example.com" --password "كلمة-مرور-قوية-جدا" --name "خالد"
```

شروط كلمة المرور: 12 حرفًا على الأقل، وثلاث فئات على الأقل من (حروف صغيرة، كبيرة، أرقام، رموز)، وليست من الكلمات الشائعة.

أو عبر متغيرات البيئة:

```powershell
$env:ADMIN_EMAIL="admin@example.com"
$env:ADMIN_PASSWORD="كلمة-مرور-قوية-جدا"
$env:ADMIN_NAME="خالد"
npm run admin:create
```

### 4.6 (اختياري) بيانات تجريبية للتطوير

```powershell
$env:SEED_DEMO_DATA="true"
npm run db:seed
```

ينشئ: 12 تصنيفًا، 16 شركة، 32 منتجًا (قطع + 3 تجميعات)، مناطق شحن لكل المحافظات، إعدادات المتجر، كوبون `WELCOME10`، وقواعد التوافق. التشغيل مرة أخرى آمن (Idempotent) ولا يكرر البيانات.

بدون `SEED_DEMO_DATA=true` سيُنشئ البذرة التصنيفات والشركات والإعدادات ومناطق الشحن فقط، بدون منتجات أو كوبون. لا يتم إنشاء أي حسابات عملاء.

### 4.7 تشغيل الموقع

```powershell
npm run dev
```

- المتجر: http://localhost:3000
- لوحة التحكم (مخفية): http://localhost:3000/admin
- دخول لوحة التحكم: http://localhost:3000/admin/login

## 6. إضافة أول منتج

### من لوحة التحكم

1. افتح `/admin` وأدخل كلمة مرور المدير، ثم افتح `/admin/products/new`.
2. أدخل الاسم العربي، وSKU فريدًا، و**السعر (أكبر من صفر)**، والضمان، والكمية.
3. اختر التصنيف (مهم: التصنيف يحدد مواصفات التوافق الجاهزة) والشركة.
4. أضف **صورة واحدة على الأقل** (PNG/JPEG/WebP/AVIF، حتى 5MB لكل صورة).
5. اختر حالة الكرتونة: **بالكرتونة الأصلية** أو **بدون كرتونة** — الحقل مطلوب ويظهر كشارة في صفحة المنتج.
6. املأ **مواصفة فنية واحدة على الأقل**. هذه القيم هي ما يعتمد عليه منشئ التجميعات:
   - **المعالج:** `socket`, `chipsetSupport`, `cpuFamily`, `tdp`, `integratedGraphics`, `minBiosVersion`
   - **اللوحة الأم:** `socket`, `chipset`, `formFactor`, `ramType`, `ramSlots`, `maxRamCapacity`, `maxRamSpeed`, `m2Slots`, `sataPorts`, `biosVersion`, `biosSupportsCpuFamilies`
   - **الرام:** `ramType`, `capacityGB`, `modules`, `speed`, `formFactor`
   - **كارت الشاشة:** `lengthMm`, `thicknessSlots`, `tdp`, `recommendedPsu`, `powerConnectors`
   - **مزود الطاقة:** `wattage`, `formFactor`, `lengthMm`, `pcie8pin`, `pcie6pin`, `pcie12vhpwr`, `cpu8pin`
   - **الكيسة:** `supportedFormFactors`, `maxGpuLengthMm`, `maxGpuThicknessSlots`, `maxCoolerHeightMm`, `radiatorSupportMm`, `maxPsuLengthMm`, `supportedPsuFormFactors`, `driveBays35`, `driveBays25`
   - **التبريد:** `coolerType`, `heightMm`, `radiatorSizeMm`, `socketSupport`
   - **التخزين:** `interface`, `formFactor`, `capacityGB`
7. اضغط "حفظ" ثم تأكد أن الحالة **نشط** ليظهر في المتجر.

> الحفظ مرفوض من السيرفر إذا غاب السعر (> 0) أو الصور أو المواصفات أو حالة الكرتونة. وبدون مواصفات التوافق سيعرض منشئ التجميعات "بيانات غير كافية" بدل نتيجة توافق.

### عبر CSV

صدّر منتجاتك من `/admin/products` لمعرفة الأعمدة، أو استخدم هذه الأعمدة:

```csv
nameAr,nameEn,sku,slug,model,categorySlug,brand,descriptionAr,price,compareAtPrice,warrantyMonths,status,type,hasBox,quantity,lowStockThreshold
```

- `categorySlug` يجب أن يطابق تصنيفًا موجودًا: `cpu`, `motherboards`, `gpu`, `ram`, `storage`, `psu`, `cases`, `cooling`, `monitors`, `peripherals`, `prebuilt-pc`, `accessories`.
- `sku` مطلوب وفريد، و`price` يجب أن يكون أكبر من صفر.
- `hasBox`: `true` (بالكرتونة) أو `false` (بدون كرتونة).
- الاستيراد لا يستورد المواصفات ولا الصور — أضفها من صفحة المنتج.

## 10. تخزين الصور وS3

### التطوير (افتراضي)

```env
STORAGE_DRIVER="local"
```

تُحفظ الصور في `public/uploads/products` و`public/uploads/payments`. هذا لا يصلح للإنتاج على منصات بلا قرص دائم.

### الإنتاج (S3 متوافق)

```env
STORAGE_DRIVER="s3"
S3_ENDPOINT="https://<account-id>.r2.cloudflarestorage.com"   # أو اتركه فارغًا لـ AWS
S3_REGION="auto"                                              # أو منطقة AWS مثل eu-central-1
S3_BUCKET="khaled-pc-store"
S3_ACCESS_KEY_ID="..."
S3_SECRET_ACCESS_KEY="..."
S3_PUBLIC_BASE_URL="https://cdn.example.com"                  # نطاق عام لقراءة الصور
S3_FORCE_PATH_STYLE="false"                                   # true مع MinIO
```

- استخدم Bucket خاصًا للكتابة مع نطاق عام للقراءة (CDN أو R2 public domain).
- أضف نطاق الصور إلى `images.remotePatterns` في `next.config.ts` إن لم يكن من النطاقات المدعومة حاليًا.
- **مهم:** واجهة S3 مكتملة برمجيًا لكنها لم تُختبر مع Bucket حقيقي في هذه البيئة. اختبرها على بيئة تجريبية قبل النشر.

## 11. الدفع وإنستاباي

- **الدفع النقدي:** عند الاستلام أو من المحل. يُسدَّد عند التسليم، والإدارة تؤكد الحالة.
- **إنستاباي:** يدوي بالكامل:
  1. فعّل إنستاباي من `/admin/settings` وأدخل اسم المستفيد والمعرّف/الرابط والتعليمات.
  2. يظهر للعميل في صفحة الطلب طريقة التحويل ورقم العملية + إمكانية رفع صورة إثبات.
  3. تصبح حالة الدفع "بانتظار مراجعة التحويل".
  4. تراجع الإدارة التحويل من صفحة الطلب (قبول/رفض). لا يصبح الطلب مدفوعًا قبل القبول.

لا تضع أي بيانات إنستاباي وهمية في الكود؛ كلها تأتي من إعدادات المتجر.

## 12. النشر على الإنترنت

### 12.1 على خادم VPS (موصى به للتحكم الكامل)

1. ثبّت Node.js 20+ وPostgreSQL وNginx.
2. انسخ المشروع ثم:

```bash
npm ci
npm run db:generate
npm run db:deploy
npm run build
```

3. اضبط `.env` للإنتاج:

```env
NODE_ENV="production"
NEXT_PUBLIC_SITE_URL="https://khaledpcstore.com"
DATABASE_URL="postgresql://USER:PASSWORD@127.0.0.1:5432/khaled_pc_store?schema=public"
STORAGE_DRIVER="s3"
```

4. شغّل التطبيق:

```bash
npm run start
```

أو عبر PM2:

```bash
npm i -g pm2
pm2 start npm --name khaled-pc-store -- run start
pm2 save
pm2 startup
```

5. Nginx كـ Reverse Proxy مع HTTPS (Let's Encrypt):

```nginx
server {
  server_name khaledpcstore.com www.khaledpcstore.com;

  client_max_body_size 10m;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

6. أنشئ المدير على السيرفر:

```bash
npm run admin:create -- --email "admin@domain.com" --password "..." --name "خالد"
```

### 12.2 على Vercel أو منصة Serverless

- اربط قاعدة PostgreSQL مُدارة (Neon / Supabase / RDS) وضع رابطها في `DATABASE_URL`.
- استخدم `STORAGE_DRIVER=s3` إلزاميًا؛ نظام الملفات غير دائم.
- نفّذ الترحيلات من جهازك أو CI:

```bash
DATABASE_URL="..." npm run db:deploy
```

- أضف كل متغيرات البيئة في لوحة المنصة، ولا ترفع `.env`.

### 12.3 قائمة فحص ما قبل النشر

- [ ] `NEXT_PUBLIC_SITE_URL` هو الدومين الحقيقي.
- [ ] `NODE_ENV=production`.
- [ ] قاعدة بيانات منفصلة عن التطوير، وكلمة مرور قوية.
- [ ] `SEED_DEMO_DATA=false` وحذف العملاء/المنتجات التجريبية.
- [ ] حساب مدير بكلمة مرور فريدة، وحذف `ADMIN_PASSWORD` من البيئة.
- [ ] `STORAGE_DRIVER=s3` واختبار رفع صورة.
- [ ] تفعيل HTTPS + HSTS على الـ Proxy.
- [ ] بيانات المتجر الحقيقية في `/admin/settings` (هاتف/واتساب/عنوان/إنستاباي).
- [ ] تشغيل `npm run typecheck && npm run lint && npm test && npm run build`.
- [ ] نسخة احتياطية أولى من قاعدة البيانات.

## 14. الأمان

### مطبّق في الكود

- كلمات مرور `scrypt` مع ملح عشوائي ومقارنة آمنة.
- جلسات عشوائية 256-bit، تُخزَّن بصمتها فقط، وكوكي `httpOnly` + `sameSite=lax` + `secure` في الإنتاج.
- صلاحيات المدير تُفحص على السيرفر في الصفحات والإجراءات، وليس في الواجهة فقط.
- قفل تسجيل الدخول بعد عدد محاولات (قابل للضبط عبر `AUTH_MAX_LOGIN_ATTEMPTS` و`AUTH_LOCK_MINUTES`).
- تحقق Zod لكل مدخلات النماذج وServer Actions.
- رفع الصور: حد للحجم، أنواع مسموحة، وفحص بايتات الترويسة (Magic Bytes).
- أسعار وإجماليات وشحن وكوبونات تُحسب على السيرفر؛ لا تُقبل أسعار من المتصفح.
- منع المخزون السالب باستخدام معاملات وقفل صفوف (`FOR UPDATE`) وقيود قاعدة البيانات.
- سجل نشاط لكل عملية حساسة (تعديل مخزون، تغيير حالة طلب، مراجعة دفع، إعدادات، مستخدمين).
- رؤوس `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`.
- لوحة التحكم `noindex` ومخفية، ولا توجد صفحات حسابات عملاء.

### توصيات إضافية للإنتاج

- HTTPS إلزامي + HSTS على الـ Reverse Proxy.
- إضافة CSP (غير مفعّلة حاليًا) بعد ضبط نطاقات الصور والسكربتات.
- تحديد معدل الطلبات (Rate Limiting) على مستوى Nginx/Cloudflare، خاصة لمسارات الدخول والتتبع.
- تشغيل PostgreSQL على الشبكة الداخلية فقط وعدم فتح المنفذ للعامة.
- تحديث الحزم دوريًا (`npm audit`) ومراجعة التبعيات.
- عدم رفع `.env` أو النسخ الاحتياطية إلى المستودع.
- مراجعة سجل النشاط دوريًا.

## 15. ما لم يكتمل بعد

هذه نسخة كاملة قابلة للتشغيل، لكن هناك حدود واضحة يجب معرفتها:

1. **الإشعارات:** لا يوجد إرسال بريد أو SMS أو واتساب آلي. روابط واتساب في المتجر ولوحة التحكم تفتح المحادثة برسالة جاهزة للإرسال اليدوي فقط، ومتغيرات SMTP موجودة كعنصر نائب. تأكيد الطلب يتم من لوحة التحكم.
2. **بوابات الدفع الإلكتروني:** لا توجد بوابة آلية (Paymob/Fawry/Stripe). إنستاباي يدوي مع إثبات، والدفع النقدي.
3. **استعادة كلمة المرور:** لا يوجد "نسيت كلمة المرور". يعيد المدير تعيين كلمة مرور أي مستخدم من لوحة المستخدمين.
4. **تأكيد البريد:** لا يوجد بريد للعملاء أصلًا؛ الشراء كزائر بدون حسابات.
5. **S3:** الواجهة جاهزة لكنها لم تُختبر مع Bucket حقيقي في هذه البيئة.
6. **تقييمات المنتجات والمفضلة:** غير منفذة.
7. **بحث متقدم:** البحث الحالي مطابقة نصية بسيطة (Contains) بدون فهرسة عربية كاملة أو Trigram.
8. **الكوبونات:** لا يوجد حد استخدام لكل عميل، ولا كوبون شحن مجاني، ولا كوبونات تلقائية.
9. **الشحن:** أسعار ثابتة حسب المحافظة، بدون تكامل مع شركات الشحن أو تتبع مباشر. رقم التتبع يُدخل يدويًا.
10. **الفاتورة:** صفحة HTML قابلة للطباعة، بدون توليد PDF على السيرفر أو فاتورة إلكترونية ضريبية.
11. **المرتجعات:** سياسات وصفحات فقط، بدون دورة RMA أو سجل استرداد مالي آلي.
12. **المخزون:** لا يوجد شراء من موردين أو أوامر توريد أو باركود.
13. **العروض والتحليلات:** لا يوجد Google Analytics أو Meta Pixel أو حملات بريدية.
14. **تعدد اللغات والعملات:** عربي وجنيه مصري فقط.
15. **الصلاحيات:** دورَا `ADMIN` و`CUSTOMER` فقط، بدون صلاحيات دقيقة (مثل موظف طلبات فقط).
16. **المهام الخلفية:** لا يوجد Queue، ولا انتهاء تلقائي لحجز المخزون للطلبات غير المؤكدة.
17. **الاختبارات:** لا توجد اختبارات E2E بالمتصفح (Playwright) أو اختبارات واجهة آلية؛ الاختبارات الحالية للسيرفر والمنطق.

## 16. استكشاف الأخطاء

### `Can't reach database server`

- تأكد أن PostgreSQL يعمل: `pg_isready -p 5432`.
- راجع المنفذ في `DATABASE_URL`. النسخة المحلية المستخدمة أثناء التطوير كانت على **5433** بسبب تعارض 5432؛ إن استخدمت نسخة محمولة شغّلها:

```powershell
pg_ctl -D "C:\path\to\pgdata" -o "-p 5433" start
```

### `Environment variable not found: DATABASE_URL`

- ملف `.env` غير موجود أو في مجلد خاطئ. انسخ `.env.example` إلى `.env` في جذر المشروع.

### Prisma Client غير محدّث

```powershell
npm run db:generate
```

### فشل اختبارات بسبب قاعدة الاختبار

- تأكد أن `khaled_pc_store_test` موجودة وأن `TEST_DATABASE_URL` صحيح.
- شغّل `npm run test:setup` ثم أعد `npm test`.

### الصور المرفوعة لا تظهر في الإنتاج

- أنت على `STORAGE_DRIVER=local` مع منصة بلا قرص دائم. فعّل S3.
- مع S3 تأكد من `S3_PUBLIC_BASE_URL` وأن الـ Bucket يسمح بالقراءة العامة (أو CDN).

### الدخول للوحة التحكم لا يعمل

- تأكد أنك تفتح `/admin/login` وأن كلمة المرور تخص حسابًا بدوره `ADMIN` ونشطًا.
- بعد تكرار المحاولات الخاطئة يتم القفل مؤقتًا وفق `AUTH_MAX_LOGIN_ATTEMPTS` و`AUTH_LOCK_MINUTES`.
- أنشئ مديرًا بـ `npm run admin:create` إذا لم يكن هناك حساب مدير.

### رسالة `next dev` عن `AGENTS.md`

- ملف يخص تعليمات Next.js للوكلاء، يُعاد إنشاؤه بواسطة `next dev`. اتركه كما هو.
